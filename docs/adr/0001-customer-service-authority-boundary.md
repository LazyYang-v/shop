# 客服继承商城买家权限，知识检索使用 WeKnora

2026-10-22 确认：首版客服提供已确认商城规则问答、商品与库存查询、本人订单与已保存物流信息查询，以及确认后取消本人未支付订单。RAG 使用 WeKnora；只收录经商城确认且带来源、版本、生效时间的政策，规则变更后旧版本不再作为有效依据。外部文章仅用于研究，不进入商城政策索引。检索缺失时明确说明暂无明确政策；订单、库存、物流和金额以业务 API 返回为准。

客服不能成为权限绕过入口：业务能力只通过受控 MCP 工具调用，复用商城现有接口及身份、归属与状态校验，不新增业务写接口，不提供数据库直连、任意查询、管理员代查或客服特权通道。未登录访客只能查询规则、商品和库存；邮箱、手机号或订单号都不是授权凭据。退款、发券、催发货、转人工不纳入首版，也不得声称已受理或已执行。

取消先展示订单号、当前状态及恢复库存、不可撤销等后果；一次性确认凭据绑定买家、订单和动作并短期有效。执行前重新验证订单归属、待支付状态和未超时条件，执行后查询 API，以最终状态及关闭原因为依据答复。重复确认不得重复执行，状态变化不得重试成取消。2026-10-22 进一步确认：买家身份仅来自服务端有效登录会话，工具参数不得包含可覆盖身份的字段。WeKnora 服务令牌不进入前端、模型上下文、日志或工具返回值；MCP 仅允许显式核实的具名工具，不支持任意 URL、SQL 或管理端透传。退出、失效及切换账号使旧授权失效。订单候选仅展示订单号、创建时间、商品摘要、金额及状态；订单号仅是过滤条件，访问失败统一表示未找到可访问订单，并对重复探测限制频率。即使只有一个候选也必须明确选定。

取消确认按钮由前端直接请求商城后端，不经过模型。模型可以提出方案，不能确认或执行取消。一次性随机凭据绑定买家、认证会话、咨询会话、订单及动作，有效期不晚于签发后两分钟和支付截止时间中的较早者；服务端只持久化凭据哈希，执行目标取自服务端记录。凭据不进入模型、聊天记录、URL 或日志。对凭据传递的具体方式仍待设计确认；“仅存在服务端且只存哈希”不能被误解为客户端无需携带任何可验证凭据。

重复确认不得重复提交业务变更，凭据使用状态及执行记录持久化；原子消费凭据、订单锁内重新校验、取消恢复库存及本次执行证据在同一事务提交，回滚则凭据不被消费。调用方管理事务，原取消 API 和客服路径共用领域逻辑，不另建提前提交“执行中”的事务。操作编号在提出方案时返回浏览器，响应丢失后按编号和当前买家权限查询执行证据。数据库操作状态为待确认、已执行、已拒绝、已失效；浏览器结果待核验和五分钟后无法核验独立于业务结果，不覆盖已提交证据。请求结果不明时不自动重发写操作，先查询核验；网络超时不能解释为未执行。关闭原因为 payment_timeout 时只报告超时关闭，buyer_cancelled 时可报告当前已取消，缺少本次执行证据时不得归因于本次客服操作。现有订单响应已有 close_reason；取消接口需单独通过 TDD 补齐订单锁内支付截止时间检查，覆盖扫描前已超时和取消与超时扫描竞争。以上为已确认设计，不表示实现已经完成。

验收使用可测用例：规则有据、缺失不编造；查询与实际状态一致；未登录、越权及非法状态请求均被拒绝；确认取消成功、重复确认不重复执行、状态变化时拒绝；关键答复可追溯到规则条目或 API 调用结果。不记录未经测量的自助解决率或成本收益。

2026-10-25 范围修订：应商城客服 Agent 平台升级需求，人工工单/转人工、服务申请（催发货、修改收货地址、发票、退换货、退款、少件、破损、错发、质保、补发、补偿的登记）、知识条目发布与检索、推荐偏好、服务通知和指标看板纳入集成客服首版；此前“转人工不纳入首版、不新增业务写接口”的限定相应废止。权限边界不变：身份仍只来自服务端有效会话，工具参数不得携带身份字段；服务申请只是登记并进入人工队列，答复明确声明不会自动退款或补偿。唯一新增的受控写路径是修改收货地址：仅在管理员将工单审结为已处理时执行，执行前在订单锁内重验订单归属与待发货状态，并要求买家地址簿当前内容与申请时快照一致才复制地址字段，执行动作与证据写入工单记录。知识引用只来自已发布、在生效区间内且商品在售的条目；同一主题存在多条有效版本时按知识冲突处理，不出引用。渠道登记只记录真实接入状态，未配置的渠道返回未开通。服务申请进度仅为只读工单查询，仍须有效买家会话、咨询绑定与未过期的明确选单；工单审结或人工回复不能作为退款到账、发票开具、补发完成的依据，仅有保存的同订单地址修改执行证据时可报告已核验执行。模型仍不持有买家身份、不直接写数据库；真实模型调用继续按既有预算与授权机制单独启用。
