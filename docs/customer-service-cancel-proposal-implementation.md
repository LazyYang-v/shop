## 实现边界

- **只提出方案，不执行取消**：新增 `propose_cancel` 模型工具与浏览器确认卡，只创建操作记录；订单状态、库存、关闭原因不变。未注册 `/cancel/confirm`、`/cancel/reconcile` 或任何模型执行/核验工具。
- **服务端明确选择**：用户点击候选订单产生的 `selected_order_id` 先由服务端校验买家归属并记录到页面实例；`propose_cancel` 必须匹配该页面记录，模型不能自报选择。
- **一次性凭据**：明文由 `secrets.token_urlsafe(32)` 生成，服务端仅持久化 SHA-256 哈希。明文只经顶层 `confirmation_card` 返回浏览器，停留在页面 JavaScript 内存；不进模型结果、聊天内容、日志、URL、`localStorage` 或 `sessionStorage`。重复消息返回 `card_unavailable`，不重发凭据。
- **模型可见范围**：MCP 结果只含操作编号、状态、商品摘要、金额、币种与期限，不含原始订单号或凭据；确认卡订单号由服务端从已记录选择补齐，严格校验响应字段集合。
- **期限与清理**：有效期为签发后 120 秒和支付截止的较早者；提出方案入口检查订单状态与支付期限，30 秒维护任务条件失效过期记录，不覆盖其他终态。没有确认/核验入口，本切片不声称完成未来确认入口的到期检查。
- **撤销与限流**：选择变化、新方案、有效交接、页面过期/LRU 淘汰及咨询清理撤销待确认凭据；续期不延长确认期限。方案每买家 5 次/分钟，订单探测每买家 10 次/分钟。
- **浏览器**：待付款订单显示申请按钮。确认卡显示操作编号、订单号、状态、金额、期限与固定后果；执行按钮禁用。卡片到期、选择变化或被新卡替代后标记不可用。续期遭遇限流或暂时网络故障时保留有效卡并延迟重试。

## 验收标准对照与限制

1. 确认卡展示订单号、状态和恢复库存/不可撤销/不恢复购物车后果；只创建操作记录，不改订单或库存。容器数据库与真实浏览器已验证。
2. 操作编号和一次性凭据绑定买家、认证会话、咨询、页面、订单和动作；期限取 120 秒与支付截止较早者。隔离数据库测试覆盖绑定与边界。
3. 只持久化哈希；凭据仅通过独立卡片响应到浏览器内存，不进入模型、聊天、日志、URL 或持久存储；“好的”等普通文字不执行。真实 Chrome、API 测试验证。
4. 交接 token 仅用于 sessionStorage，90 秒有效、30 秒续期、同页单在途，恢复前台立即续期；Playwright 验证重复 `visibilitychange` 只发一次请求，容器 Chrome 验证刷新交接。
5. 有效交接撤销前驱；丢失/过期交接新建实例，确认卡到期不延长；关闭页面不承诺即时撤销。容器 Chrome 验证刷新后旧卡不恢复，API 测试覆盖交接撤销。
6. 页面上限 10、周期清理 30 秒、条件更新不覆盖终态，重启后维护任务恢复。隔离数据库测试覆盖；没有确认/核验入口，因此未来确认入口的即时凭据检查由后续执行票验收。
