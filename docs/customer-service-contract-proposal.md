## 最新相关性方案修订

用户后续授权确定并验证“先明确主题及适用条件、无法确定则拒答”的方案。[确定性保护记录](customer-service-relevance-guard.md)及可复现参考脚本已完成40项离线检查与12题实际候选回放。其资格门替代下文历史的最低hybrid分数阈值要求：分数仅排序，全句规则明确范围后按可信登记复核候选，不以任意阈值放行。有限合成覆盖未证明生产泛化，未知主题/条件保持澄清，生产答复仍不放行。下文阈值定标条目保留为历史取舍，不再要求为不适合跨查询比较的分数硬定τ。

## 1. 推荐选择与影响

| 决定 | 推荐值 | 理由及影响 |
|---|---|---|
| 编排 | Python服务端确定性分流，复合问题进入受限工具循环；首版不引入LangGraph | 现有六种工具和确认协议可由显式状态控制；复杂度增加时再评估框架 |
| 模型 | 已确认DeepSeek API、deepseek-flash | 仍需真实工具调用兼容性验证；不借用其他产品凭据 |
| 首版输出 | 非流式JSON；仅完整、校验后的答复和卡片返回浏览器 | 避免部分输出被误当作确认结果；首字延迟较长 |
| 模型推理模式 | 优先关闭额外推理；仅在官方参数与该模型支持情况核实后设置 | 此处是行为选择，不猜测API字段；不支持时回到审核，禁止静默切换模型 |
| Rerank | 首版接受当前MCP hybrid融合，不额外加入模型Rerank | 已知该路径未启用模型Rerank；用户附条件接受首版取舍；必须以固定问题集评估及阈值定标，不宣称检索质量已达标 |
| 政策索引 | 每个政策版本使用独立、不可变的WeKnora文档；商城持权威登记 | 避免同ID更新后无法区分索引旧正文与新正文；生产政策不原地覆盖 |
| 政策可见性 | 首版不启用Wiki、ask、原文读取等额外工具，不缓存政策回答或订单事实 | 限制权限与失效传播问题；每轮重新检查登记及业务事实 |

收费模型验证另行提供请求预算并获得授权；批准本稿不自动授权消费。仅有模型返回不能证明业务执行成功。

## 2. 数量、时间和预算

下表为附条件批准的设计参数，未表示实现或测试通过。相关度阈值仍待实测定标；所有限制在服务端执行。配置缺失时客服服务不启动对应能力，不能默默放宽。

| 项目 | 推荐值与计数方式 |
|---|---|
| 消息长度 | 1–2000个Unicode码点；HTTP JSON正文最大16 KiB，先限制字节再解析 |
| 单会话并发 | 同一认证或匿名会话最多1个咨询消息在处理；多标签页冲突返回busy。确认和核验不受消息并发锁阻塞 |
| 页面实例 | 每会话10个；达到上限时按last_used_at、实例ID稳定排序淘汰最久未使用实例，先撤销其待确认凭据和交接标识再新建；同会话锁内原子完成，多进程不得超额。last_used_at取已鉴权有效请求的服务端时间（含续期）；实例闲置10分钟到期。失败则整笔回滚并返回503，不静默丢失 |
| 咨询上下文 | 闲置30分钟结束，最长24小时；新上下文不能继承旧确认资格；新页面实例结束旧卡资格仍按已确认交接规则 |
| 消息限流 | 每会话滚动60秒最多20条；同来源IP每分钟60条，IP只来自连接或明确可信代理配置 |
| 本人订单号过滤 | 每买家每分钟10次，跨会话合计 |
| 提出取消方案 | 每买家每分钟5次；每页面最多1个待确认方案，新方案使该页面旧方案失效 |
| 确认入口 | 每买家每分钟10次；本地限流拒绝也不能让浏览器假定未执行，未知结果继续核验；取消永不自动重试 |
| 核验入口 | 每买家每分钟60次，独立额度；锁竞争返回processing |
| 页面续期 | 每实例每分钟4次；与咨询/确认/核验分开计数，避免续期耗尽业务额度 |
| 依赖并发 | 单部署模型最多2个在途请求，WeKnora检索最多4个；无空位立即busy，不建无界等待队列 |
| 业务分页 | 商品和订单默认10条、最多20条；页码1–100，超范围受控拒绝；数据变化可能改变后续页 |
| 工具预算 | 每轮总计6次：政策检索≤1、商品查询（列表+详情）≤2、订单查询（列表+详情）≤2、提出方案≤1；各项不能挪用。实际尝试含只读重试均消耗所属额度，因此政策检索本轮不重试。最多4次模型请求，同轮工具顺序执行；相同工具及规范化参数重复调用直接拒绝，不再请求依赖 |
| WeKnora检索 | 显式批准KB，hybrid、limit=5；最多选3个已核验引用，每片段最多1000字符。须通过最低相关度阈值；数值需按固定版本实际score语义和标注问题集定标，尚未确定，定标前政策答复不放行。不把RRF分数当概率，不套用任意0.7等阈值 |
| 模型上下文 | 本地计量输入上限12000 tokens，输出上限1500 tokens；不能可靠计量则拒绝模型分支，不能只按字符猜预算 |
| 会话模型额度 | 每会话每日累计输入+输出最多50000 tokens；额度不足时停止模型分支，保留确定性查询；计费失败/超时按预留额度保守计入 |
| 部署模型额度 | 每日输入+输出合计最多500000 tokens；按UTC自然日统计，发送前预留最坏额度，成功后据usage结算；跨进程原子计数 |
| 金额预算 | token额度不是人民币消费上限；首次收费测试/上线前按当时官方价格给出成本估算并另批金额，不启用无人值守付费运行 |
| 检索期限 | 单次最多5秒连接及读取合计；整个检索步骤最多10秒，临时故障最多重试一次且共享期限 |
| 模型期限 | 单请求最多20秒、整轮最多45秒；不自动重试模型请求，避免重复消费；超时未结束的依赖请求仍占并发额度直到结束 |
| 普通商城查询期限 | 单次最多3秒；只读临时故障最多一次重试，受整轮45秒约束 |
| 确认/核验期限 | 确认浏览器等待10秒后进入未知结果；核验单请求3秒，操作锁等待最多1秒（已确认）；不能按超时推断回滚 |
| 核验节奏 | 2/4/8秒，之后15秒（已确认）；每个间隔加0–500毫秒随机抖动，5分钟窗口按单调时钟硬截止 |
| 已确认期限 | 确认凭据min(签发+120秒,支付截止)；交接标识90秒、30秒续期；续期不延长确认期限 |
| 清理 | 每30秒使用数据库条件更新失效过期方案、条件删除到期实例及秘密；另每日清理达到保留期限的证据。锁定并复核状态及期限，多进程幂等，不覆盖终态；实例删除与其凭据/交接资格撤销同事务。任务失败记录脱敏错误并在后续周期重试，不阻断正常请求；所有入口即时验期，不能依赖任务及时执行 |

限流需共享原子存储；不可用时拒绝新增模型调用和方案签发，返回service_unavailable，不静默回退成每进程额度。已经签发的确认与核验继续走数据库授权和独立入口保护，不能因模型限额拒绝核验。入口保护故障时返回不可用；客户端按未知结果协议处理。

## 3. 数据与保留期限

| 数据 | 推荐处理 |
|---|---|
| 聊天及工具上下文 | 仅服务端短期保留；闲置30分钟或绝对24小时后删除，同事务删除关联确认凭据哈希、交接标识，并将待确认操作置失效；保留最小终态证据。入口到期立即拒绝，即使后台清理失败也不能使用残留凭据。首版无历史咨询查询，未登录也绑定服务端匿名会话 |
| 页面/交接记录 | 过期后30秒清理周期回收；操作证据保留不可逆实例关联摘要，不保留交接原值 |
| 确认秘密 | 至少32随机字节，服务端仅哈希；明文只在当次浏览器响应及内存；终态立即移除可验证的凭据哈希 |
| 操作及执行证据 | 终态起保留30天；到期后核验返回统一operation_unavailable，不再展示成功凭证；保留期内身份失效仍不可访问。聊天删除或操作编号丢失后，仍可在本人订单详情独立查看status及close_reason；它只证明订单现状，不能归因本次客服执行 |
| 运行日志 | 保留7天，仅请求标识、工具名、耗时、受控错误、计数。禁止字段：密码、会话ID及Cookie、Authorization/API密钥、CSRF Token、确认凭据原值及哈希、交接标识、完整地址、电话、聊天、政策正文、商品描述、订单号、端点标识。请求/响应正文与异常对象不得绕过清单自动记录 |
| 模型用量账本 | 保留30天，仅会话不可逆标识、token预留/结算及时间；不存提示词 |
| 政策登记及版本正文 | 使用中及其引用证据保留期内不可删除；撤回后至少30天且不得早于最后关联证据到期。撤回正文不能重新作为当前依据 |

这里只约束商城自有存储。DeepSeek/WeKnora及基础设施的日志、备份和数据保留需要单独核实，不能承诺本地删除等于外部副本全部清除。不得把用户输入中的个人信息直接原样送给模型；先裁剪工具字段并遮盖可识别的电话/地址等内容，识别不完整属于需评测的限制。

## 4. 政策权威映射与失效处理

推荐登记字段：policy_id、version、scope_key（政策适用主题及条件集合）、source_label、受控source_ref、effective_from、effective_to、status、knowledge_base_id、knowledge_id、canonical_content_hash。时间UTC，区间采用[from,to)，to可空。版本唯一，来源链接只能指向商城批准的政策来源，不能直接使用检索结果中的任意URL。

发布流程：先登记staging并检查同scope_key的区间冲突；导入独立文档并验证对应内容；验证成功才原子切换active。替换时同事务撤回旧登记；已撤回旧索引即使仍返回也被拒绝。新文档未就绪不发布新版本，不伪称生效。登记发布/导入是维护流程，不注册给模型，不在本轮新增管理功能。

检索时显式限定库；用返回KB+文档ID匹配登记，再按服务端当前时间、状态及scope_key检查。由于文档不可变，ID对应固定政策版本；不依赖正文或摘要自称版本。没有映射的命中不进入模型政策上下文。检测登记冲突则返回policy_conflict；登记读取失败返回policy_unavailable。

摘要及其他片段只用于找到登记项。模型可引用的依据从商城已登记的规范正文截取，不把无法校验的派生摘要当作权威原文。引用由服务端生成，带政策ID、版本、来源和生效区间；回答完成前再次检查引用仍有效，若发布变更则撤销该政策结论，返回policy_unavailable供用户重新查询。

检索成功且没有达到相关度阈值的候选：policy_no_match，措辞“未检索到足够相关的政策依据”，不扩大为商城不存在政策。先验证映射与有效性再应用相关度；候选全因失效/未知映射被排除时优先返回policy_unavailable并记录candidate_filtered，固定措辞“相关依据已失效或待维护，暂无法确认”。top5后过滤可能漏掉有效政策，不宣称召回率得到补偿。

撤回流程：商城登记立即置withdrawn，阻断引用；维护流程请求删除精确旧文档并记录cleanup_pending，低量三模式检索确认无目标命中后记cleanup_verified。删除失败保持withdrawn并重试维护清理，不恢复引用；检测到索引残留则该政策范围不放行。知识库维护写能力不进入客服只读端点。现有证据只证明两次合成条目在观察窗口内删除后无命中，不能保证“失效瞬间旧文档绝不会被WeKnora原始检索命中”。用户要求旧文档不能命中是验收目标，异步删除窗口内仍由商城拒绝；若要求平台原始检索零残留且无任何窗口，目前不能承诺，该项保持阻塞，不将后置过滤当作同等实现。

尚需验证：同ID篡改不能发布、不同版本独立ID、未来/过期边界、区间重叠、撤回后旧命中、未知映射、摘要不含版本、引用期间版本切换。#1需验证补偿的可行性；后续#4承担完整产品路径实现，不能用本稿代替测试。

## 5. 浏览器HTTP契约建议

统一前缀/api/customer-service；所有接口同源、Cache-Control: no-store，响应含request_id、queried_at（UTC ISO8601）、status、data，错误另含code及安全message。请求JSON拒绝未知字段。所有POST复用shop_session、X-CSRF-Token、Origin；先通过现有/api/auth/csrf建立匿名会话。订单能力额外要求买家身份。

| 方法及路径 | 精确请求字段（?为可选） | 核心结果 |
|---|---|---|
| POST /pages | handoff_token? | page_instance_id、consultation_id、handoff_token、handoff_expires_at；合法交接继承咨询上下文并撤销前驱待确认；无效交接新建上下文，不带回旧卡 |
| POST /pages/renew | page_instance_id、handoff_token | handoff_expires_at；不轮换标识、不延长确认；失效返回page_expired |
| POST /messages | page_instance_id、consultation_id、client_message_id、text?、selected_order_id?（二者至少一个） | reply、cards、citations；确认卡独立字段confirmation_card，不进入模型消息或工具结果 |
| POST /cancel/confirm | page_instance_id、consultation_id、operation_id、confirmation_token | executed/rejected/invalidated/rolled_back；凭据绑定所有字段，订单及动作仅取服务端记录 |
| POST /cancel/reconcile | page_instance_id、consultation_id、operation_id | executed/rejected/invalidated/processing；仍校验原始绑定，不允许其他页面恢复前驱执行资格 |

client_message_id为随机UUID，仅去重咨询请求：同会话+页面+标识正文一致时返回已有结果或processing；正文不同返回message_conflict。去重记录保留到咨询到期；任何重放都不能再次签发凭据。已含确认卡的响应不重发原凭据，返回已有操作摘要和card_unavailable，用户需重新提出方案；浏览器不自动重发咨询POST。

确认卡字段：operation_id、order_number、product_summary、total、currency、expires_at、confirmation_token。金额为现有API格式的精确金额，不用模型计算；卡片字段与日志自动脱敏。模型仅见操作摘要及operation_id。所有随机标识长度上限128字符，非UUID标识按服务端生成格式校验。

前端按HTTP + status + code处理，禁止匹配message文案。客服新接口按下表统一；现有普通商城API状态码不在#1中修改。涉及资源ID的不存在和他人资源统一403及相同code/措辞，避免用404与403区分归属。列表没有本人候选是200 empty，不属于对某个资源ID的存在性查询。

| 场景 | HTTP / status / code | 前端动作及边界 |
|---|---|---|
| 页面创建成功 | 201 / ok | 保存页面内存标识及允许的交接标识 |
| 查询成功或本人列表为空 | 200 / ok或empty | 展示核验信息；空列表统一“未找到可访问的记录” |
| 订单能力未登录或认证失效 | 401 / error / authentication_required | 引导登录，停止核验；匿名政策/商品请求不因匿名而401 |
| 无权限、不属于本人、未知资源ID | 403 / error / resource_unavailable | 一律“未找到可访问的记录”；不泄露不存在还是属于他人 |
| CSRF或Origin错误 | 403 / error / forbidden | 停止请求，不能从中推断业务结果 |
| 订单状态不满足、页面/消息冲突 | 409 / rejected或error / state_conflict、page_conflict、message_conflict | 展示状态已变化或要求重新操作；已持久化拒绝附操作证据 |
| 凭据过期、撤销或已失效 | 410 / invalidated / credential_expired或credential_invalidated | 移除旧卡；不重发取消。已执行记录仍按现有证据返回executed，不改写为过期 |
| 页面过期 | 410 / error / page_expired | 建新实例；不复活旧凭据 |
| 消息仍处理或核验锁竞争 | 425 / processing / processing | 消息只查看已有请求结果；核验按既定退避，绝不重发取消 |
| 服务不可用、依赖异常、预算耗尽 | 503 / unavailable或partial / dependency_unavailable、budget_exhausted | 有核验数据则按部分结果表展示；确认无确定业务响应时进入未知结果核验 |
| 文本>2000字符、正文>16KiB | 422 / error / message_too_long；413 / error / payload_too_large | 拒绝并提示缩短，不静默截断 |
| 其他字段校验、限流 | 422 / error / invalid_input；429 / error / rate_limited | 修正输入或按Retry-After秒数等待；取消不自动重试 |
| 确认完整回滚 | 200 / rolled_back / transaction_rolled_back | 明确本次未执行，可由用户在期限内再次确认；不启动核验 |
| 确认已执行、核验终态证据 | 200 / executed、rejected或invalidated | 按证据展示；核验读取已有rejected证据可200，确认当次状态冲突用409 |

确认503、连接中断或无响应统一结果未知；只有明确status=rolled_back且服务端确认完整回滚才可提示重新确认。425是核验处理中而非持久化业务执行中状态。

code集合：authentication_required、forbidden、resource_unavailable、page_expired、page_conflict、message_conflict、state_conflict、credential_expired、credential_invalidated、processing、busy、invalid_input、message_too_long、payload_too_large、rate_limited、budget_exhausted、tool_budget_exhausted、turn_timeout、transaction_rolled_back、dependency_unavailable、policy_no_match、policy_conflict、policy_unavailable、operation_unavailable、internal_error。接口外围错误不能成为业务未执行证明；返回request_id便于定位，不返回堆栈。

结果核验只能读取同原始会话/咨询/页面绑定的操作证据；刷新交接后若需要跨页面恢复展示，要单独定义只读证据访问，不借本稿自动扩大原核验权限。首版刷新可使旧卡失效并引导查看订单，不承诺找回旧咨询操作卡。

## 6. 六个模型工具Schema建议

所有对象additionalProperties=false。缺省参数由服务端填充；模型无法提供身份、页面、咨询、确认凭据、端点、URL或SQL。工具调用上下文由服务端绑定。工具并不等于直接开放同名WeKnora工具。

| 工具 | 允许参数及限制 |
|---|---|
| search_policy | question:非空字符串≤2000字符；category?:受控登记类别，≤64字符 |
| list_products | keyword?:≤100字符；category?:≤64字符；page?:1–100；page_size?:1–20，默认10 |
| get_product | product_id:UUID |
| list_my_orders | status?:pending_payment/pending_shipment/pending_receipt/completed/closed；order_number?:≤64字符；page?:1–100；page_size?:1–20 |
| get_my_order | order_id:UUID |
| propose_cancel | order_id:UUID；必须匹配当前页面由用户明确点击候选选择产生的服务端选择记录，否则拒绝。选择不能由模型自报 |

订单选择随/messages的固定卡片交互需要受控输入：新增可选selected_order_id:UUID，与text至少一个必填；它只记录本人的明确选择，不触发取消，身份/归属重新校验。模型不能伪造浏览器点击；前端不得将模型正文解析成选择事件。页面内存保存选择，服务端绑定到当前页面及咨询；切换选择使原待确认方案失效。

输出均为request_id、queried_at、status、data。商品金额/库存/订单字段取已有业务服务，分页返回items、page、page_size、has_more。订单结果不含地址、电话及内部用户ID。政策输出来自权威登记；空订单列表status=empty，越权及不存在详情统一resource_unavailable；提出方案返回proposed及摘要，凭据不在工具输出。超出工具次数/时间预算返回受控失败，禁止自动换通用工具继续。

### 达到预算和超时的确定行为

| 触发条件 | 服务端行为 | 前端及答复 |
|---|---|---|
| 分类调用上限、6次总上限或4次模型请求上限 | 不再调用模型或工具，不再签发方案；用确定性模板组装已核验结果 | status=partial，code=tool_budget_exhausted；逐项列出已完成及未完成原因，不声称办理成功 |
| 整轮45秒超时 | 停止调度，关闭请求级任务；已发依赖未终止仍占并发额度。方案若已提交但响应未安全交付，条件失效待确认方案及删除凭据；清理失败入口也拒绝该过期/作废资格，并后台补清理 | 有核验结果返回partial + turn_timeout；无结果503。不能附带旧确认卡；提示未完成部分，不能称取消已执行 |
| 模型用量/时间额度不足 | 不再发送模型请求，保留可独立完成的确定性只读结果 | 有数据partial + budget_exhausted，无数据503；不让模型补写未核验部分 |
