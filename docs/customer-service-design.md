## 已确认的工具边界

模型仅可调用六类工具：商城政策检索、商品查询、商品详情、本人订单列表、本人订单详情、提出取消方案。参数不得含 user_id、buyer_id 等身份选择字段。订单号过滤始终限定当前买家。查询结果不包含收货地址或电话。

提出取消方案只创建操作记录和确认卡，不改变订单状态。确认执行能力不注册给模型；按钮直接请求商城后端，校验认证会话、CSRF、请求来源，再由受控执行路径复用原取消领域逻辑。外部 WeKnora MCP 仅开放已核实的检索工具，不承担买家授权。

工具统一返回请求标识、查询时间、结果状态和可展示数据。政策原文、商品名称、描述及其他工具返回自由文本均为数据，不能改变系统规则、身份、工具权限或执行流程；其中的“忽略规则”“调用工具”等文字不作为指令。秘密、确认凭据、内部堆栈不得进入模型可见结果。

## 已确认的取消确认

必须先由买家选定候选订单，即使只有一单也不自动选中。候选卡仅展示订单号、创建时间、商品摘要、金额和状态。跨买家订单与不存在订单统一返回未找到可访问订单，并限制订单号探测频率。

凭据由服务端随机生成，绑定买家、认证会话、咨询会话、订单与动作。服务端仅持久化哈希；明文仅在签发响应返回浏览器，在页面内存保留，以确认请求正文提交。不进入模型、日志、URL、聊天记录、localStorage 或 sessionStorage。页面实例由服务端生成并绑定认证会话，凭据额外绑定页面实例。仅在有效交接完成时，撤销前驱实例的未执行凭据；标识过期、丢失或交接失败则只建立新实例，不承诺即时撤销前驱。旧凭据由两分钟有效期和会话校验兜底，不保证关闭标签页立即撤销。多个标签页实例互不撤销，单会话实例数量须设上限并清理过期实例。实例标识不进入模型、聊天记录、URL 或浏览器持久存储。Q15 已确认有限例外：仅用于刷新交接的标识可保存在 sessionStorage。标识由服务端随机签发、一次性使用、绑定认证会话、约一分钟有效并在交接后轮换，不进入 Cookie、localStorage、URL、日志或模型上下文；不能查询订单、签发确认凭据或执行取消。交接成功撤销前驱未执行凭据。会话不匹配时拒绝交接并新建实例；重复标签页导致冲突时保守撤销旧确认卡再新建实例，不保证复制标签页完全互不影响。Q18 已确认：活跃页面约每三十秒更新交接标识，并为一次续期失败保留适当宽限；后台恢复时通过 visibilitychange 立即尝试续期。续期独立于确认凭据，不延长确认凭据期限。无有效交接标识的刷新无法识别前驱，按只建立新实例处理；后台暂停、网络失败不能保证即时续期。Q20 已确认：标识有效期九十秒、每三十秒续期，同页仅一个续期请求在途；续期仅条件延长仍有效、未消费且与当前实例和会话匹配的标识，已消费标识不可复活。仅交接成功才消费并轮换标识。已过期时建立新实例；确认凭据有效期不变。实例数量上限的具体值与清理频率仍须在协议清单中显式标注建议值。

有效期为签发后两分钟与支付截止时间的较早者。退出、会话失效、账号切换、订单状态变化后旧授权失效。一次性使用通过数据库原子条件更新或唯一约束保证，禁止先查后写。执行目标以凭据绑定的服务端记录为准，不接受客户端替换订单或动作。

## 已确认的政策治理

商城侧登记政策来源、版本、生效时间与状态；WeKnora 只作检索索引，其版本过滤能力需实际核实。发布时检查生效区间，检索后核实有效版本，过期历史引用不得作为当前依据。

2026-10-23 #4：按用户批准的合成范围实现了明确标注的虚构演示登记与进程内索引替身，覆盖发布区间检查、检索后登记核对、交付前复核及 no-match/冲突/不可用区分；真实 WeKnora/真实政策路径仍关闭，详见[合成政策实施记录](customer-service-policy-implementation.md)。

无匹配、政策冲突、检索服务不可用分别返回，不能混用。冲突时回答“当前政策依据存在冲突，暂无法确认”并记录问题，不由模型自行择一。规则缺失不以通用电商常识补全。外部研究资料不进入商城政策索引。

## 已确认的恢复与证据

只读查询遇网络或临时故障最多重试一次，身份失效、无权访问、参数错误不重试。写操作永不自动重试。政策检索失败不阻断独立订单查询。执行结果不明仅查询核验。

Q12–Q14 已确认：执行记录和前端核验状态分别建模，不持久化前置“执行中”状态。

操作记录允许迁移：待确认 → 已执行 / 已拒绝 / 已失效。“已执行”表示取消及本次执行证据已在同一事务提交，不等同于提交后的订单展示查询已成功。“已拒绝”表示服务端已核实条件不满足并提交拒绝结果；临时故障导致事务回滚不记录为业务拒绝。凭据消费、锁定订单、校验归属/状态/截止时间、关单恢复库存及执行证据须同事务提交；回滚则全部不生效，凭据不被消费。不得为“执行中”单独提前提交事务。

原取消领域函数接受调用方 Session，由调用方管理事务，原 API 与客服执行路径共享唯一的校验及关单逻辑；此事务组织调整属于未来客服实现，本次独立超时修复尚未实施该调整。提交后独立查询订单展示，查询不参与授权判断。

方案签发时向浏览器返回操作编号；确认请求提交操作编号和凭据，目标订单和动作仍从服务端记录取得。核验操作编号必须重新校验当前登录会话及买家归属，编号不构成授权。响应丢失后按操作编号发起受保护的结果核验，不依赖已消费凭据；直接查订单只能说明当前状态，不能代替本次执行证据。核验可能撤销待确认凭据，属于写操作，不能注册为只读工具。

前端核验状态允许：等待响应 → 已核验 / 结果待核验；结果待核验 → 已核验 / 无法核验。结果待核验表示浏览器未收到确定结果、事务可能已提交，不是已提交的业务中间态。五分钟窗口内只请求结果核验、不重放业务写入；核验本身可原子撤销待确认凭据，须登录会话、CSRF 和来源校验。超时后显示无法核验并保留操作编号、引导查看订单，不自动重发取消请求或声称已转人工。前端核验超时不覆盖数据库中的真实执行结果，后续读到权威证据仍可展示。仅服务端能确定回滚且凭据仍有效时，提示未执行、可重新确认；网络超时本身不能作此断言。

未确认凭据过期、退出或被新方案替代时，操作为已失效，与执行拒绝区分。业务状态不会因前端核验状态改变而回退。

Q16 已确认：业务拒绝原因与证据和已拒绝状态同事务提交，凭据作废；明确回滚保持待确认且有效凭据可由用户重新确认。只有服务端明确返回事务未提交的错误响应，浏览器才可视为确定回滚；进程中断、连接超时或响应丢失均为结果未知。操作编号随机不可猜测，核验始终校验登录会话和归属，不能借编号探测他人操作。

执行须先锁操作记录，凭据原子消费与订单锁及业务修改在同一事务内。核验也须取得同一操作记录的排他锁或等效串行化保护：短暂限时获取失败可有限重试，仍失败返回处理中、请稍候，不以旧的待确认记录推断回滚。读取及判断在锁保护下完成；Q17 已确认：取得锁后如仍待确认，必须通过状态仍为待确认的条件更新将其置为已失效并撤销凭据，再提交结果，阻止尚未到达数据库的迟到执行请求。已执行或已拒绝则返回已有证据；已失效返回相同失效结果。核验为写接口，只作用于当前买家自己的操作，须同时验证会话、CSRF 和来源；重复核验幂等，迟到确认返回明确状态错误，不取消订单。

只有响应丢失、连接中断、超时或异常导致没有明确结果时才进入结果核验。收到明确的事务已回滚、未执行响应时，不调用核验接口，以免撤销仍有效的确认凭据；用户可自行再次点击。措辞分别为本次未执行可重新确认、未发现已提交执行且旧确认已撤销、以及有本次执行证据的已执行成功。核验不注册给模型。Q19 已确认：单次取锁最多一秒，失败返回处理中；从结果未知起按二、四、八秒退避，之后每十五秒一次，加入少量随机抖动，总窗口五分钟。每次请求前检查会话，服务端每次重新鉴权；身份失效或收到已执行、已拒绝、已失效时停止轮询。窗口结束显示无法核验并保留操作编号、引导查看订单；支持用户手动重新检查一次。取消执行不自动重试，普通只读查询临时故障最多重试一次。

即使无人再次确认或核验，待确认记录也必须在凭据到期后通过后台条件更新自动转为已失效；执行和核验入口仍即时检查到期时间，不能依赖清理任务及时运行来授权。后台任务仅更新仍为待确认且已过期的记录，不覆盖已执行、已拒绝或已失效结果。

订单响应已有 close_reason，buyer_cancelled 与 payment_timeout 可区分。缺少本次执行证据时只陈述当前状态。只有本次执行证据和最终订单状态一致，才可称本次取消成功。
